## Fluxo básico [#basic-flow]

<Steps>
  <Step title="Defina a classe de erro">
    Herde de `I18nErrorBase<TMeta>` e defina em `TMeta` as informações que você quer usar para gerar a mensagem.
  </Step>
  <Step title="Registre as mensagens de cada idioma">
    Use `setErrorMessage` para registrar as mensagens correspondentes à classe e ao idioma.
  </Step>
  <Step title="Troque o idioma e leia message">
    Troque com `setGlobalConfig({ lang })` do Valibot e acesse `error.message`.
  </Step>
</Steps>

```ts
import { setGlobalConfig } from "valibot";
import { I18nErrorBase, setErrorMessage } from "i18n-error-base";

class BusinessRuleError extends I18nErrorBase<{ code: string; limit: number }> {
  public constructor(meta: { code: string; limit: number }) {
    super(meta, ({ code, limit }) => `Code: ${code}, Limit: ${limit}`);
  }
}

setErrorMessage(
  BusinessRuleError,
  ({ code, limit }) => `コード: ${code}、制限: ${limit}`,
  "ja",
);

const error = new BusinessRuleError({ code: "ERR", limit: 50 });

setGlobalConfig({ lang: "ja" });
console.log(error.message); // コード: ERR、制限: 50

setGlobalConfig({ lang: "en" });
console.log(error.message); // Code: ERR, Limit: 50
```

## Definindo a classe de erro [#define-error-class]

`TMeta` é o tipo das informações extras que você usa para gerar a mensagem. Ele fica salvo como `error.meta` e também é passado para a função de `setErrorMessage`.

```ts
import { I18nErrorBase } from "i18n-error-base";

class NotFoundError extends I18nErrorBase<{ resource: string }> {}

const error = new NotFoundError({ resource: "user" }, "fallback message");
console.log(error.meta); // { resource: "user" }
```

O segundo argumento do construtor é uma string ou uma função `(meta) => string`. No terceiro argumento, você pode passar as mesmas opções de `Error`, como `{ cause }`.

```ts
class TestError extends I18nErrorBase<{ code: string }> {}

const cause = new Error("original");
const error = new TestError({ code: "ERR" }, "something went wrong", { cause });
console.log(error.cause === cause); // true
```

Se você definir `TMeta` como `undefined`, pode omitir o `meta`.

```ts
class NoMetaError extends I18nErrorBase<undefined> {}

const a = new NoMetaError("no meta");
const b = new NoMetaError(undefined, "no meta");
console.log(a.meta); // undefined
```

:::note
Não foi feito para você dar `new` direto em `I18nErrorBase`. Crie sempre uma classe concreta herdada para usar. Como o destino do registro de mensagens é separado por construtor (`this.constructor`), uma mensagem que você registrou na classe pai não é herdada pela classe filha.
:::

## Registrando mensagens [#register-message]

`setErrorMessage` registra a função que cria a mensagem para uma classe e um idioma.

```ts
import { I18nErrorBase, setErrorMessage } from "i18n-error-base";

class TestError extends I18nErrorBase<{ code: string }> {}

setErrorMessage(TestError, ({ code }) => `エラーコード: ${code}`, "ja");
setErrorMessage(TestError, "something went wrong", "en");
```

Se você passar uma string, ela é convertida internamente para `() => text`. Você também pode indicar o idioma como um array de strings.

```ts
const message = ({ code }: { code: string }) => `エラーコード: ${code}`;
setErrorMessage(TestError, message, ["ja", "ko", "zh"]);
```

Se você registrar de novo a mesma classe e o mesmo idioma, ele sobrescreve. Independentemente do resultado de `instanceof`, o conteúdo registrado só é usado quando o construtor da hora do registro e o da hora da leitura são o mesmo.

:::warning[Cuidado com o acesso antes do registro]
A mensagem padrão em forma de função é avaliada no primeiro acesso e fica em cache. Se você ler `message` em um idioma ainda não registrado antes de chamar `setErrorMessage`, esse valor padrão fica fixado. Por isso, registre as mensagens de cada idioma, de preferência, antes de criar as instâncias.
:::

## Trocando de idioma [#switch-language]

Você troca o idioma na configuração global do Valibot. `message` consulta o `lang` atual a cada acesso.

```ts
import { setGlobalConfig } from "valibot";

setGlobalConfig({ lang: "ja" });
console.log(error.message); // 日本語の登録メッセージ

setGlobalConfig({ lang: "en" });
console.log(error.message); // 英語の登録メッセージ or 既定メッセージ
```

O padrão de `lang` quando não está configurado é `"en"`. Se você pedir um idioma sem registro, ele usa como fallback a mensagem padrão passada ao construtor.

```ts
setErrorMessage(BusinessRuleError, () => "日本語メッセージ", "ja");

setGlobalConfig({ lang: "fr" });
console.log(error.message); // "Code: ERR, Limit: 50"（既定メッセージ）
```

## Prefixo [#prefix]

Se você configurar `static prefix` na classe, ele é colocado no início da mensagem resolvida. Vale tanto para as mensagens traduzidas quanto para a mensagem padrão.

```ts
class PrefixedError extends I18nErrorBase<{ code: string }> {
  static {
    this.prefix = "[ERROR] ";
  }
}

setErrorMessage(PrefixedError, ({ code }) => `code is ${code}`, "ja");
const error = new PrefixedError({ code: "ERR" }, "fallback");

setGlobalConfig({ lang: "ja" });
console.log(error.message); // "[ERROR] code is ERR"

setGlobalConfig({ lang: "en" });
console.log(error.message); // "[ERROR] fallback"
```

Se você não configurar, ele retorna como está, sem prefixo.

## Comportamento como Error [#error-behavior]

- `error instanceof Error`, `instanceof I18nErrorBase` e `instanceof` da classe concreta são todos `true`
- `message` é enumerável (aparece em `Object.keys(error)`)
- `String(error)` / `error.toString()` incluem a mensagem resolvida (ex.: `"Error: ..."`)
- `cause` é guardado com `new TestError(meta, message, { cause })`. Como polyfill para ambientes de execução antigos, há um tratamento que atribui `options.cause` quando `cause` não é suportado

## Padrões comuns [#common-patterns]

### Fixando a mensagem padrão no construtor [#fix-default-message-in-constructor]

```ts
class BusinessRuleError extends I18nErrorBase<{ code: string; limit: number }> {
  public constructor(meta: { code: string; limit: number }, options?: ErrorOptions) {
    super(meta, ({ code, limit }) => `Code: ${code}, Limit: ${limit}`, options);
  }
}
```

Quem chama só precisa se preocupar com o `meta`, e você evita duplicar o texto padrão (aqui, em inglês).

### Registrando vários idiomas de uma vez [#register-multiple-languages]

```ts
setErrorMessage(MyError, "エラーが発生しました", ["ja"]);
setErrorMessage(MyError, "An error occurred", ["en", "en-US"]);
```

Os códigos de idioma não são normalizados. `"en"` e `"en-US"` são tratados como chaves diferentes, então registre explicitamente todos os códigos que você precisa.
