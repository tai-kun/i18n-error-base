## Flujo básico [#basic-flow]

<Steps>
  <Step title="Definir la clase de error">
    Herede de `I18nErrorBase<TMeta>` y defina como `TMeta` la información que desea usar para generar mensajes.
  </Step>
  <Step title="Registrar mensajes para cada idioma">
    Registre con `setErrorMessage` el mensaje correspondiente a la clase y al idioma.
  </Step>
  <Step title="Cambiar el idioma y leer message">
    Cambie con `setGlobalConfig({ lang })` de Valibot y acceda a `error.message`.
  </Step>
</Steps>

```ts
import { setGlobalConfig } from "valibot";
import { I18nErrorBase, setErrorMessage } from "i18n-error-base";

class BusinessRuleError extends I18nErrorBase<{ code: string; limit: number }> {
  public constructor(meta: { code: string; limit: number }) {
    super(meta, ({ code, limit }) => `Code: ${code}, Limit: ${limit}`);
  }
}

setErrorMessage(
  BusinessRuleError,
  ({ code, limit }) => `コード: ${code}、制限: ${limit}`,
  "ja",
);

const error = new BusinessRuleError({ code: "ERR", limit: 50 });

setGlobalConfig({ lang: "ja" });
console.log(error.message); // コード: ERR、制限: 50

setGlobalConfig({ lang: "en" });
console.log(error.message); // Code: ERR, Limit: 50
```

## Definir la clase de error [#define-error-class]

`TMeta` es el tipo de información adicional usada para generar mensajes. Se conserva como `error.meta` y también se pasa a la función de `setErrorMessage`.

```ts
import { I18nErrorBase } from "i18n-error-base";

class NotFoundError extends I18nErrorBase<{ resource: string }> {}

const error = new NotFoundError({ resource: "user" }, "fallback message");
console.log(error.meta); // { resource: "user" }
```

El segundo argumento del constructor es una cadena o una función `(meta) => string`. Como tercer argumento se pueden pasar opciones como `{ cause }`, igual que en `Error`.

```ts
class TestError extends I18nErrorBase<{ code: string }> {}

const cause = new Error("original");
const error = new TestError({ code: "ERR" }, "something went wrong", { cause });
console.log(error.cause === cause); // true
```

Si `TMeta` es `undefined`, se puede omitir `meta`.

```ts
class NoMetaError extends I18nErrorBase<undefined> {}

const a = new NoMetaError("no meta");
const b = new NoMetaError(undefined, "no meta");
console.log(a.meta); // undefined
```

:::note
`I18nErrorBase` no está pensado para instanciarse directamente con `new`. Cree siempre una clase concreta heredada para usarla. Como el destino del registro de mensajes se distingue por unidad de constructor (`this.constructor`), los mensajes registrados en la clase padre no se heredan en la clase hija.
:::

## Registrar mensajes [#register-message]

`setErrorMessage` registra una función creadora de mensajes para una clase y un idioma.

```ts
import { I18nErrorBase, setErrorMessage } from "i18n-error-base";

class TestError extends I18nErrorBase<{ code: string }> {}

setErrorMessage(TestError, ({ code }) => `エラーコード: ${code}`, "ja");
setErrorMessage(TestError, "something went wrong", "en");
```

Si se pasa una cadena, internamente se convierte a `() => text`. El idioma también se puede especificar como un arreglo de cadenas.

```ts
const message = ({ code }: { code: string }) => `エラーコード: ${code}`;
setErrorMessage(TestError, message, ["ja", "ko", "zh"]);
```

Si se vuelve a registrar la misma clase y el mismo idioma, se sobrescribe. Independientemente del resultado de `instanceof`, el contenido registrado solo se usa cuando el constructor en el momento del registro y en el momento de la referencia son idénticos.

:::warning[Atención al acceso previo al registro]
La forma funcional del mensaje predeterminado se evalúa y se almacena en caché en el primer acceso. Si se lee `message` en un idioma no registrado antes de `setErrorMessage`, ese valor predeterminado quedará fijado. Como regla general, registre los mensajes de cada idioma antes de crear la instancia.
:::

## Cambiar el idioma [#switch-language]

El idioma se cambia con la configuración global de Valibot. `message` consulta el `lang` actual en cada acceso.

```ts
import { setGlobalConfig } from "valibot";

setGlobalConfig({ lang: "ja" });
console.log(error.message); // 日本語の登録メッセージ

setGlobalConfig({ lang: "en" });
console.log(error.message); // 英語の登録メッセージ or 既定メッセージ
```

El valor predeterminado cuando `lang` no está configurado es `"en"`. Si se solicita un idioma no registrado, se recurre al mensaje predeterminado pasado al constructor.

```ts
setErrorMessage(BusinessRuleError, () => "日本語メッセージ", "ja");

setGlobalConfig({ lang: "fr" });
console.log(error.message); // "Code: ERR, Limit: 50"（既定メッセージ）
```

## Añadir un prefijo [#prefix]

Si se configura `static prefix` en la clase, se concatena al principio del mensaje resuelto. Se aplica tanto a los mensajes traducidos como al mensaje predeterminado.

```ts
class PrefixedError extends I18nErrorBase<{ code: string }> {
  static {
    this.prefix = "[ERROR] ";
  }
}

setErrorMessage(PrefixedError, ({ code }) => `code is ${code}`, "ja");
const error = new PrefixedError({ code: "ERR" }, "fallback");

setGlobalConfig({ lang: "ja" });
console.log(error.message); // "[ERROR] code is ERR"

setGlobalConfig({ lang: "en" });
console.log(error.message); // "[ERROR] fallback"
```

Si no se configura, se devuelve tal cual sin prefijo.

## Comportamiento como `Error` [#error-behavior]

- Tanto `error instanceof Error` como `instanceof I18nErrorBase` e `instanceof` de la clase concreta son `true`
- `message` es enumerable (está incluido en `Object.keys(error)`)
- `String(error)` / `error.toString()` incluyen el mensaje resuelto (p. ej.: `"Error: ..."`)
- `cause` se conserva con `new TestError(meta, message, { cause })`. Como polyfill para entornos de ejecución antiguos, se incluye un proceso que asigna `options.cause` cuando `cause` no es compatible

## Patrones comunes [#common-patterns]

### Fijar el mensaje predeterminado en el constructor [#fix-default-message-in-constructor]

```ts
class BusinessRuleError extends I18nErrorBase<{ code: string; limit: number }> {
  public constructor(meta: { code: string; limit: number }, options?: ErrorOptions) {
    super(meta, ({ code, limit }) => `Code: ${code}, Limit: ${limit}`, options);
  }
}
```

El lado que llama solo necesita tener en cuenta `meta`, y se evita duplicar el texto predeterminado (aquí en inglés).

### Registrar varios idiomas a la vez [#register-multiple-languages]

```ts
setErrorMessage(MyError, "エラーが発生しました", ["ja"]);
setErrorMessage(MyError, "An error occurred", ["en", "en-US"]);
```

No se normalizan los códigos de idioma. `"en"` y `"en-US"` se tratan como claves distintas, por lo que registre explícitamente los códigos necesarios.
