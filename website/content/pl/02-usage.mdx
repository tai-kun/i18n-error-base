## Podstawowy przepływ [#basic-flow]

<Steps>
  <Step title="Zdefiniuj klasę błędu">
    Rozszerz `I18nErrorBase<TMeta>` i zdefiniuj w `TMeta` dane do generowania komunikatu.
  </Step>
  <Step title="Zarejestruj komunikaty dla języków">
    Zarejestruj komunikat dla klasy i języka przez `setErrorMessage`.
  </Step>
  <Step title="Przełącz język i odczytaj message">
    Przełącz przez `setGlobalConfig({ lang })` i odczytaj `error.message`.
  </Step>
</Steps>

```ts
import { setGlobalConfig } from "valibot";
import { I18nErrorBase, setErrorMessage } from "i18n-error-base";

class BusinessRuleError extends I18nErrorBase<{ code: string; limit: number }> {
  public constructor(meta: { code: string; limit: number }) {
    super(meta, ({ code, limit }) => `Code: ${code}, Limit: ${limit}`);
  }
}

setErrorMessage(
  BusinessRuleError,
  ({ code, limit }) => `コード: ${code}、制限: ${limit}`,
  "ja",
);

const error = new BusinessRuleError({ code: "ERR", limit: 50 });

setGlobalConfig({ lang: "ja" });
console.log(error.message); // コード: ERR、制限: 50

setGlobalConfig({ lang: "en" });
console.log(error.message); // Code: ERR, Limit: 50
```

## Definiowanie klasy błędu [#define-error-class]

`TMeta` to dane pomocnicze do generowania komunikatu. Są przechowywane w `error.meta` i przekazywane do zarejestrowanych funkcji.

```ts
import { I18nErrorBase } from "i18n-error-base";

class NotFoundError extends I18nErrorBase<{ resource: string }> {}

const error = new NotFoundError({ resource: "user" }, "fallback message");
console.log(error.meta); // { resource: "user" }
```

Drugi argument to ciąg lub funkcja `(meta) => string`. Trzeci to opcje `Error`, np. `{ cause }`.

```ts
class TestError extends I18nErrorBase<{ code: string }> {}

const cause = new Error("original");
const error = new TestError({ code: "ERR" }, "something went wrong", { cause });
console.log(error.cause === cause); // true
```

`TMeta` ustawione na `undefined` pozwala pominąć `meta`.

```ts
class NoMetaError extends I18nErrorBase<undefined> {}

const a = new NoMetaError("no meta");
const b = new NoMetaError(undefined, "no meta");
console.log(a.meta); // undefined
```

:::note
Nie używaj `new` bezpośrednio; zawsze dziedzicz. Rejestracje są przypisane do klasy, więc rejestracja rodzica nie przechodzi na dzieci.
:::

## Rejestrowanie komunikatów [#register-message]

`setErrorMessage` rejestruje funkcje tworzące komunikat dla klasy i języka.

```ts
import { I18nErrorBase, setErrorMessage } from "i18n-error-base";

class TestError extends I18nErrorBase<{ code: string }> {}

setErrorMessage(TestError, ({ code }) => `エラーコード: ${code}`, "ja");
setErrorMessage(TestError, "something went wrong", "en");
```

Dozwolone są też ciągi. Języki można podać jako tablicę.

```ts
const message = ({ code }: { code: string }) => `エラーコード: ${code}`;
setErrorMessage(TestError, message, ["ja", "ko", "zh"]);
```

Ponowna rejestracja tej samej klasy i języka nadpisuje wpis. Dotyczy tylko zgodnych konstruktorów przy rejestracji i odczycie, nie przez `instanceof`.

:::warning[Uwaga na dostęp przed rejestracją]
Odczytanie `message` najpierw utrwala wartość domyślną. Zarejestruj przed utworzeniem instancji.
:::

## Przełączanie języków [#switch-language]

Przełącz w globalnej konfiguracji Valibot. `message` odwołuje się do bieżącego `lang` przy każdym odczycie.

```ts
import { setGlobalConfig } from "valibot";

setGlobalConfig({ lang: "ja" });
console.log(error.message); // 日本語の登録メッセージ

setGlobalConfig({ lang: "en" });
console.log(error.message); // 英語の登録メッセージ or 既定メッセージ
```

Nieustawiony `lang` to `"en"`. Niezarejestrowane języki używają domyślnego komunikatu z konstruktora.

```ts
setErrorMessage(BusinessRuleError, () => "日本語メッセージ", "ja");

setGlobalConfig({ lang: "fr" });
console.log(error.message); // "Code: ERR, Limit: 50"（既定メッセージ）
```

## Dodawanie prefiksu [#prefix]

`static prefix` jest dodawany na początku rozwiązanego komunikatu. Dotyczy komunikatów tłumaczonych i domyślnych.

```ts
class PrefixedError extends I18nErrorBase<{ code: string }> {
  static {
    this.prefix = "[ERROR] ";
  }
}

setErrorMessage(PrefixedError, ({ code }) => `code is ${code}`, "ja");
const error = new PrefixedError({ code: "ERR" }, "fallback");

setGlobalConfig({ lang: "ja" });
console.log(error.message); // "[ERROR] code is ERR"

setGlobalConfig({ lang: "en" });
console.log(error.message); // "[ERROR] fallback"
```

Gdy nie jest ustawiony, zwracany jest bez zmian.

## Zachowanie jako Error [#error-behavior]

- `error instanceof Error`, `instanceof I18nErrorBase` i `instanceof <klasa konkretna>` zwracają `true`
- `String(error)` / `error.toString()` zawierają rozwiązany komunikat (np. `"Error: ..."`)
- `cause` jest przechowywane przez `{ cause }`

## Typowe wzorce [#common-patterns]

### Ustalenie komunikatu domyślnego w konstruktorze [#fix-default-message-in-constructor]

```ts
class BusinessRuleError extends I18nErrorBase<{ code: string; limit: number }> {
  public constructor(meta: { code: string; limit: number }, options?: ErrorOptions) {
    super(meta, ({ code, limit }) => `Code: ${code}, Limit: ${limit}`, options);
  }
}
```

Strona wywołująca przekazuje tylko `meta`, co pozwala uniknąć powielania domyślnego tekstu.

### Rejestrowanie wielu języków naraz [#register-multiple-languages]

```ts
setErrorMessage(MyError, "エラーが発生しました", ["ja"]);
setErrorMessage(MyError, "An error occurred", ["en", "en-US"]);
```

Kody języków nie są normalizowane. `"en"` i `"en-US"` to osobne klucze, więc zarejestruj jawnie potrzebne kody.
