## Основний процес [#basic-flow]

<Steps>
  <Step title="Визначити клас помилки">
    Успадкуйте `I18nErrorBase<TMeta>` і визначте в `TMeta` дані для генерації повідомлень.
  </Step>
  <Step title="Зареєструвати повідомлення для кожної мови">
    Зареєструйте повідомлення для класу й мови через `setErrorMessage`.
  </Step>
  <Step title="Перемкнути мову та прочитати message">
    Перемкніть через `setGlobalConfig({ lang })` і прочитайте `error.message`.
  </Step>
</Steps>

```ts
import { setGlobalConfig } from "valibot";
import { I18nErrorBase, setErrorMessage } from "i18n-error-base";

class BusinessRuleError extends I18nErrorBase<{ code: string; limit: number }> {
  public constructor(meta: { code: string; limit: number }) {
    super(meta, ({ code, limit }) => `Code: ${code}, Limit: ${limit}`);
  }
}

setErrorMessage(
  BusinessRuleError,
  ({ code, limit }) => `コード: ${code}、制限: ${limit}`,
  "ja",
);

const error = new BusinessRuleError({ code: "ERR", limit: 50 });

setGlobalConfig({ lang: "ja" });
console.log(error.message); // コード: ERR、制限: 50

setGlobalConfig({ lang: "en" });
console.log(error.message); // Code: ERR, Limit: 50
```

## Визначення класу помилки [#define-error-class]

`TMeta` — допоміжні дані для генерації повідомлень. Зберігається в `error.meta` і передається зареєстрованим функціям.

```ts
import { I18nErrorBase } from "i18n-error-base";

class NotFoundError extends I18nErrorBase<{ resource: string }> {}

const error = new NotFoundError({ resource: "user" }, "fallback message");
console.log(error.meta); // { resource: "user" }
```

Другий аргумент — рядок або функція `(meta) => string`. Третій — `{ cause }` та інші опції `Error`.

```ts
class TestError extends I18nErrorBase<{ code: string }> {}

const cause = new Error("original");
const error = new TestError({ code: "ERR" }, "something went wrong", { cause });
console.log(error.cause === cause); // true
```

При `TMeta` як `undefined` `meta` можна опустити.

```ts
class NoMetaError extends I18nErrorBase<undefined> {}

const a = new NoMetaError("no meta");
const b = new NoMetaError(undefined, "no meta");
console.log(a.meta); // undefined
```

:::note
Не використовуйте `new` напряму; завжди наслідуйте. Реєстрації — за класом, тому батьківські не успадковуються дітьми.
:::

## Реєстрація повідомлень [#register-message]

`setErrorMessage` реєструє фабричні функції за класом і мовою.

```ts
import { I18nErrorBase, setErrorMessage } from "i18n-error-base";

class TestError extends I18nErrorBase<{ code: string }> {}

setErrorMessage(TestError, ({ code }) => `エラーコード: ${code}`, "ja");
setErrorMessage(TestError, "something went wrong", "en");
```

Рядки також допустимі. Мови можна задавати масивом.

```ts
const message = ({ code }: { code: string }) => `エラーコード: ${code}`;
setErrorMessage(TestError, message, ["ja", "ko", "zh"]);
```

Повторна реєстрація того самого класу й мови перезаписує. Діє лише при збігу конструкторів під час реєстрації та звернення, а не через `instanceof`.

:::warning[Увага щодо доступу до реєстрації]
Перше читання `message` фіксує значення за замовчуванням. Реєструйте до створення екземплярів.
:::

## Перемикання мови [#switch-language]

Перемикайте глобальним налаштуванням Valibot. `message` при кожному читанні звертається до поточного `lang`.

```ts
import { setGlobalConfig } from "valibot";

setGlobalConfig({ lang: "ja" });
console.log(error.message); // 日本語の登録メッセージ

setGlobalConfig({ lang: "en" });
console.log(error.message); // 英語の登録メッセージ or 既定メッセージ
```

Неналаштоване `lang` — `"en"`. Незареєстровані мови використовують повідомлення за замовчуванням із конструктора.

```ts
setErrorMessage(BusinessRuleError, () => "日本語メッセージ", "ja");

setGlobalConfig({ lang: "fr" });
console.log(error.message); // "Code: ERR, Limit: 50"（既定メッセージ）
```

## Додавання префікса [#prefix]

`static prefix` додається на початок розв'язаного повідомлення. Діє і для перекладених, і для повідомлень за замовчуванням.

```ts
class PrefixedError extends I18nErrorBase<{ code: string }> {
  static {
    this.prefix = "[ERROR] ";
  }
}

setErrorMessage(PrefixedError, ({ code }) => `code is ${code}`, "ja");
const error = new PrefixedError({ code: "ERR" }, "fallback");

setGlobalConfig({ lang: "ja" });
console.log(error.message); // "[ERROR] code is ERR"

setGlobalConfig({ lang: "en" });
console.log(error.message); // "[ERROR] fallback"
```

Якщо не налаштовано, повертається як є.

## Поведінка як Error [#error-behavior]

- `error instanceof Error`, `instanceof I18nErrorBase` та `instanceof` конкретного класу — усі `true`
- `String(error)` / `error.toString()` містять розв'язане повідомлення (наприклад `"Error: ..."`)
- `cause` зберігається через `{ cause }`

## Поширені шаблони [#common-patterns]

### Фіксування повідомлення за замовчуванням у конструкторі [#fix-default-message-in-constructor]

```ts
class BusinessRuleError extends I18nErrorBase<{ code: string; limit: number }> {
  public constructor(meta: { code: string; limit: number }, options?: ErrorOptions) {
    super(meta, ({ code, limit }) => `Code: ${code}, Limit: ${limit}`, options);
  }
}
```

На стороні виклику достатньо передати лише `meta`, що уникає дублювання тексту за замовчуванням.

### Групова реєстрація кількох мов [#register-multiple-languages]

```ts
setErrorMessage(MyError, "エラーが発生しました", ["ja"]);
setErrorMessage(MyError, "An error occurred", ["en", "en-US"]);
```

Нормалізація мовних кодів не виконується. `"en"` і `"en-US"` — окремі ключі, тому потрібні коди реєструйте явно.
