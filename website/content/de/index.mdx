Eine Basisklasse zur Erweiterung von `Error`, die `message` synchron mit der globalen Spracheinstellung (`lang`) von Valibot dynamisch umschaltet.

```ts
import { setGlobalConfig } from "valibot";
import { I18nErrorBase, setErrorMessage } from "i18n-error-base";

class NotFoundError extends I18nErrorBase<{ resource: string }> {}

setErrorMessage(NotFoundError, ({ resource }) => `リソースが見つかりません: ${resource}`, "ja");
setErrorMessage(NotFoundError, ({ resource }) => `Resource not found: ${resource}`, "en");

const error = new NotFoundError({ resource: "user" }, "fallback message");

setGlobalConfig({ lang: "ja" });
console.log(error.message); // リソースが見つかりません: user

setGlobalConfig({ lang: "en" });
console.log(error.message); // Resource not found: user
```

Da `lang` bei jedem Zugriff auf `message` zum aktuellen Zeitpunkt gelesen wird, kann die Sprache ohne Neuerstellung der Instanz gewechselt werden. Für Sprachen ohne Registrierung wird auf die im Konstruktor übergebene Standardnachricht zurückgegriffen.

## Funktionen [#features]

- Löst `message` dynamisch synchron mit `getGlobalConfig()` / `setGlobalConfig({ lang })` von Valibot auf
- Sprachspezifische Nachrichten werden nachträglich mit `setErrorMessage` registriert. Es können auch Funktionen registriert werden, die `meta` erhalten
- Für Sprachen ohne Registrierung wird auf die Standardnachricht des Konstruktors zurückgegriffen
- Mit `static prefix` pro Klasse kann ein Präfix am Anfang der Nachricht hinzugefügt werden
- Behält `meta` im Konstruktor und übergibt es an Nachrichten-Erzeugungsfunktionen
- Da die Klasse von `Error` erbt, funktionieren `instanceof Error`, `cause` und `stack` wie gewohnt
- Nachrichten werden in einer `WeakMap` gespeichert, sodass nicht mehr benötigte Klassen per Garbage Collection freigegeben werden

## Funktionsweise [#how-it-works]

Der Konstruktor von `I18nErrorBase` definiert `message` als Getter. Bei jedem Zugriff wird es in folgender Reihenfolge aufgelöst.

1. Holt `lang` aus `getGlobalConfig()`. Wenn nicht gesetzt, ist es `"en"`
2. Falls eine mit `setErrorMessage` registrierte Funktion für (Klasse × lang) existiert, wird sie mit `meta` ausgeführt
3. Andernfalls wird die im Konstruktor übergebene Standardnachricht (Zeichenkette oder Funktionsergebnis) zurückgegeben
4. Falls `static prefix` gesetzt ist, wird es am Anfang verkettet

:::tip
Die Funktionsform der Standardnachricht wird beim ersten Zugriff ausgewertet und danach zwischengespeichert. Nachrichten registrierter Sprachen werden bei jedem Zugriff aus `meta` neu erzeugt, sodass Sprachwechsel sofort wirksam werden.
:::
