与 Valibot 全局语言设置（`lang`）联动、动态切换 `message` 的 `Error` 继承用基类。

```ts
import { setGlobalConfig } from "valibot";
import { I18nErrorBase, setErrorMessage } from "i18n-error-base";

class NotFoundError extends I18nErrorBase<{ resource: string }> {}

setErrorMessage(NotFoundError, ({ resource }) => `リソースが見つかりません: ${resource}`, "ja");
setErrorMessage(NotFoundError, ({ resource }) => `Resource not found: ${resource}`, "en");

const error = new NotFoundError({ resource: "user" }, "fallback message");

setGlobalConfig({ lang: "ja" });
console.log(error.message); // リソースが見つかりません: user

setGlobalConfig({ lang: "en" });
console.log(error.message); // Resource not found: user
```

由于每次访问 `message` 时都会参照当时的 `lang`，因此无需重新创建实例即可切换语言。对于未注册的语言，将回退到传给构造函数的默认消息。

## 特性 [#features]

- 与 Valibot 的 `getGlobalConfig()` / `setGlobalConfig({ lang })` 联动，动态解析 `message`
- 使用 `setErrorMessage` 在之后注册各语言的消息，也可以注册接收 `meta` 的函数
- 对于未注册的语言，回退到构造函数的默认消息
- 可通过类级别的 `static prefix` 在消息开头添加前缀
- 在构造函数中保留 `meta`，并将其传递给消息生成函数
- 由于继承自 `Error`，`instanceof Error`、`cause`、`stack` 可照常使用
- 消息保存位置为 `WeakMap`，不再需要的类会被垃圾回收

## 工作原理 [#how-it-works]

`I18nErrorBase` 的构造函数将 `message` 定义为 getter，每次访问时按以下顺序解析。

1. 从 `getGlobalConfig()` 获取 `lang`，未设置时为 `"en"`
2. 如果存在经 `setErrorMessage` 注册的（类 × lang）函数，则传入 `meta` 并执行
3. 否则返回传给构造函数的字符串或函数结果（默认消息）
4. 如果设置了 `static prefix`，则拼接到开头

:::tip
默认消息的函数形式会在首次访问时求值，此后会被缓存。已注册语言的消息会在每次访问时根据 `meta` 重新生成，因此语言切换会立即生效。
:::
